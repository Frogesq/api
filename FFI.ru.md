# FFI: C-типы, память и внешние библиотеки

## Подключение

```lua
local ffi = require("ffi")
client.log(ffi.os, ffi.arch, ffi.abi("64bit"))
```

Встроен cffi-lua поверх libffi. Require cffi возвращает тот же модуль. Это не LuaJIT: не используйте jit-функции, LuaJIT-суффиксы числовых литералов или примеры с bit без адаптации. Обычная Lua 5.5-синтаксика и cffi-контракт остаются раздельными.

FFI даёт native-доступ внутри процесса. Проверки обычного Lua API не распространяются на произвольные адреса FFI. Неверный размер, ABI, поток callback или освобождённый указатель могут завершить весь процесс; api.protect не является обработчиком всех native faults.

## Объявления и значения

`ffi.cdef(text)` разбирает C-объявления: typedef, структуры и прототипы. Он не загружает функцию и не ищет внутренний C++-метод по имени. `ffi.typeof` создаёт повторно используемый CType. `ffi.new` выделяет CData; `ffi.cast` преобразует значение к C-типу.

```lua
local ffi = require("ffi")
ffi.cdef[[
typedef struct { float x; float y; float z; } ExamplePoint;
]]
local Point = ffi.typeof("ExamplePoint")
local point = ffi.new(Point)
point.x, point.y, point.z = 10, 20, 30
client.log(ffi.tonumber(point.x), ffi.sizeof(Point))
```

Имя структуры в примере — ваш собственный тип, не layout игровой сущности. Для реального native-объекта нужны точные типы, размеры, выравнивание и версия структуры.

Массивы C индексируются с **0**, Lua-массивы обычно с 1. Pointer arithmetic работает в единицах размера указанного C-типа, а не всегда в байтах. Приведение указателя не проверяет, что адрес допустим или жив.

## Память и строки

```lua
local ffi = require("ffi")
local buffer = ffi.new("uint8_t[16]")
ffi.fill(buffer, 16, 0)
ffi.copy(buffer, "Hello", 5)
local text = ffi.string(buffer, 5)
client.log(text)
```

`ffi.copy(dst,src,length)` и `ffi.fill(dst,length,byte)` не знают ёмкость произвольного указателя. Передавайте размер, который действительно помещается. `ffi.string(ptr,length)` копирует указанное число байт в Lua-строку. Без length функция ищет NUL; не используйте этот режим для бинарных данных или буфера без гарантированного терминатора.

`ffi.sizeof`, `ffi.alignof`, `ffi.offsetof` помогают исследовать **объявленный вами C-тип**. Они не доказывают, что он соответствует объекту игры. `ffi.addressof(value)` получает адрес объекта, но не продлевает автоматически жизнь всех связанных ресурсов. Держите исходного владельца живым.

`ffi.istype` проверяет тип. `ffi.type` возвращает cdata для CData/CType и обычное имя типа в остальных случаях. `ffi.tonumber` переводит числовое значение; не храните произвольный 64-битный адрес через промежуточный floating-point number. Для native-адресов удерживайте указатель/целочисленный CData подходящего типа.

`ffi.eval` разбирает числовой литерал, а не произвольное C-выражение. `ffi.toretval` — преобразование CData к Lua-представлению, предусмотренному реализацией. Полные параметры всех методов: [справочник FFI](FFI_INDEX.ru.md).

## DLL и вызовы

`ffi.load(name,global)` открывает библиотеку. На Windows имя/путь задаётся UTF-8 строкой. Загружается native-код, а не Lua-модуль. Используйте библиотеку x64 с экспортированным C-интерфейсом и известной сигнатурой. `ffi.C` предоставляет отдельный namespace доступных C-символов; не предполагайте, что любая функция любой загруженной DLL автоматически находится в нём.

Объявление должно точно соответствовать библиотеке: возвращаемый тип, порядок аргументов, pointer/value, размер целого, packing, constness и calling convention там, где он применим. C++-ссылка, перегруженный метод или объект с vtable не превращаются в безопасный C API после произвольного typedef.

Удерживайте объект библиотеки всё время использования её функций и callback. Сначала остановите её работу и снимите регистрации callback, затем освобождайте зависимые данные. `ffi.errno` относится к C errno; это не универсальный код ошибки Windows API.

## Callback и время жизни

Callback — C-функциональный указатель на Lua-функцию. Его нужно удерживать отдельной переменной, пока native-код хранит адрес. Освобождение через callback:free допустимо только после того, как native-код гарантированно перестал его использовать. Callback:set меняет функцию у существующего callback; он не меняет чужой прототип.

Не передавайте Lua callback библиотеке, которая вызывает его из неизвестного фонового потока. Не позволяйте Lua-ошибке неожиданно пересечь native-стек библиотеки; обработайте ожидаемые ошибки на своей стороне и верните допустимый C-результат.

`ffi.gc(value,finalizer)` связывает finalizer с владельцем. `ffi.gc(value,nil)` снимает его. Сборщик мусора не знает правила вашего native-протокола: finalizer не заменяет явный shutdown, остановку worker-потока или отписку от callback. Из finalizer нельзя обращаться к уже уничтоженным объектам Skeet.

## Внутренние функции Skeet

У этого выпуска нет публичного custom C SDK и полной таблицы private-адресов. Указатель, смещение, vtable index и внутренний layout могут измениться при сборке или обновлении. FFI сам не обеспечивает их совместимость и не переносит старую структуру на новый бинарник.

Для предоставленных возможностей используйте обычный Lua API. Для своей внешней библиотеки держите стабильный экспортированный C-контракт и проверяйте её версию. Не трактуйте наличие FFI как обещание, что любое вмешательство сохранит работоспособность стрельбы или защитит память от чтения.

Сложный пример владения библиотекой, callback, видеобуфером и звуком — [Doom](games/DOOM.ru.md). Он использует внешний libretro core и требует отдельных файлов.
