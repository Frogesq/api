# Штатные настройки и бинды

## Как найти поле

Скинченджер настраивается только в штатном меню. Категория `changer`
недоступна через Lua settings и не включается в `settings.list()`.

Имя функции в C++ и подпись пункта меню не обязательно совпадают с ключом Lua. Используйте `settings.list(filter)`; фильтр ищет подстроку в category. Каждый элемент содержит `category`, `name`, `type`, `count`, `writable`.

```lua
for _, field in ipairs(settings.list("anti aim")) do
    client.log(field.category, field.name, field.type, field.writable)
end
```

Передавайте точные `category` и `name` из результата. Не добавляйте русскую локализованную подпись вместо ключа. Неизвестное поле вызывает ошибку.

## Чтение, постоянная запись и override

| Функция | Поведение |
|---|---|
| `settings.get(category, name)` | Копия текущего значения |
| `settings.set(category, name, value)` | Изменение базового значения настройки |
| `settings.override(category, name, value)` | Временное значение от этого скрипта |
| `settings.override(category, name, nil)` | Снять только свой override |

Выбирайте override для функции, которая должна действовать, пока включён скрипт. При выгрузке его overrides снимаются автоматически. `settings.set` не является временным изменением и при выгрузке не возвращается к старому значению.

Если поле переопределяют несколько скриптов, действует последнее записанное значение активного владельца. Снятие одного override может открыть значение другого. Пока действует override, `set` меняет сохраняемую базу, а не обязательно видимое прямо сейчас значение.

Тип value должен соответствовать полю: boolean для переключателя, number для числового поля, `{r,g,b,a}` для цвета, таблица нужной формы для массива или поддерживаемой структуры. `count` описывает размер зарегистрированного поля, но не заменяет проверку значения. Для `custom` запись разрешена только у явно поддерживаемых полей; смотрите `writable`.

Аимбот, сканирование, lagcomp, параметры стрельбы и peek assistance не доступны для записи через этот API. Косметические поля типа color доступны, даже если расположены в боевой категории. Чтение таких настроек и их биндов сохраняется. Вызовы set/override/bind не обходят `writable`.

Состояние заряда DT для отрисовки доступно через `combat.double_tap()`, другие
булевы переключатели — через `indicators.get(category, name)`. См.
[свои индикаторы](INDICATORS.ru.md). Значение `settings.get("ragebot", "double tap")`
показывает только включение функции, а не готовность заряда.

Рейдж автоматически выбирает режим отдельно для каждого врага. Если по предварительной
оценке корпус и ноги заведомо нелетальны, сканирует вручную выбранные области
с обычным Min Damage. Эта оценка учитывает броню и падение урона на дистанции
для текущей позиции стрельбы и позы цели. Если урон потенциально
летальный, сначала проверяет корпус и ноги. Только подтверждённые lethal damage
и precise hitchance заменяют ручной набор. Закрытое тело, недостаточный фактический
урон или hitchance возвращают скан вручную выбранных областей с обычным Min Damage.
Это правило общее для всех оружейных профилей; у дробовиков число дробин само по себе
не подтверждает летальность залпа. Без ручных областей возврат не добавляет голову.
Force Baim исключает
голову и использует обычный минимальный урон для корпуса и ног. Руки и шея исключены.
Отдельный переключатель и бинд Lethal Baim удалены. Ключ `lethal b-aim` больше
не зарегистрирован: его старое значение не может выключить постоянное поведение,
обращение к нему из Lua возвращает ошибку неизвестной настройки.
Поля `hitboxes` и `bone hitboxes` в категориях `ragebot - <weapon>` восстановлены
для ручного выбора и доступны Lua только для чтения. `hitboxes` сохраняет 6 слотов:
Head, Chest, Stomach, Arms (игнорируется), Legs, Feet. `bone hitboxes` сохраняет
19 индексов; шея 1 и руки 13–18 игнорируются даже в старом конфиге. Lethal Baim
и Force Baim выбирают тело/ноги независимо от этих полей и не переписывают их.
У легитбота ручной выбор сохранён. Индивидуальные `bone scale N`,
общие `head scale`/`body scale` рейджа сохраняют прежние ключи и доступны для чтения.
Наблюдение `combat.hitboxes` по-прежнему может возвращать все захваченные хитбоксы;
это снимок геометрии, а не список текущего сканирования рейджа.

Центры корпуса и ног проверяются общей пачкой раньше боковых точек.
Если подходящего центра нет, проверяются до двух приоритетных боковых точек
каждого допустимого хитбокса из настроенного облака. После подтверждения урона
и точного шанса поиск тела этого врага завершается. В автоматическом режиме
урон обязан быть смертельным, в Force Baim достаточно обычного min damage.
Обычный ручной скан сохраняет полное настроенное облако выбранных костей,
включая голову. Автоматическая body-точка сохраняет требование lethal damage
во всех проверках, даже если её кость также включена вручную. Ограничение боковых точек
тела может исключить узкий прострел через другую часть облака.
Результаты разных врагов участвуют в общем сравнении.
`hit chance` и `minimum hitchance` — разные пороги:
Force shot при выполнении своего условия может использовать меньший второй
порог. Само значение `hit chance=55` поэтому не означает 55% для каждого
выстрела. Эти боевые настройки доступны Lua только для чтения.

Min Damage задаёт порог расчётного урона. В текущей реализации значение выше 100
означает летальный порог по расчётному здоровью цели, а не буквальные 118 урона
или HP + 18. При расчёте убийства двумя выстрелами этот порог может составлять
половину расчётного здоровья с округлением вверх.
Проверка разброса учитывает достижение требуемого урона, однако разрешённый
выстрел с низким hitchance может фактически нанести меньше Min Damage даже
при попадании в голову. Расчёт центрального луча не гарантирует урон реальной
пули: её путь зависит от разброса и серверной обработки попадания.

Ragebot Information удалён. Ключи `ragebot / ragebot information` и
`ragebot / information color` больше не доступны через settings.get/set/override
и не создают бинд. Удалите обращения к ним из старых скриптов; неизвестный ключ
вызывает штатную ошибку настройки. Старые конфиги могут содержать эти записи,
но они не включают отрисовку. `ragebot / scan point color` сохраняется для
облаков редактора.

[Falling Sperm](FALLING_SPERM.ru.md) поддерживает цвет и основные параметры капель.
Отдельных bloom-полей у него нет. [Трассер Skeet](IMPACTS.ru.md) включается одним
переключателем и поддерживает RGB, отдельный bloom, его радиус и интенсивность.
Параметры стиля, длительности и толщины трассера недоступны. Старые значения этих полей в конфигах
игнорируются, а запрос неизвестного имени через Lua возвращает ошибку.

## Штатные виджеты

### Свои manual arrows

Lua может заменить штатные стрелки, не выключая manual anti-aim. В `paint`
скройте нужные стороны через временный override:

```lua
settings.override("anti aim", "manual left arrow", false)
settings.override("anti aim", "manual right arrow", false)
```

Штатные стрелки рисуются после Lua `paint`, поэтому override учитываются в том же
кадре. Для возврата передайте `nil`; хост также освобождает override при выгрузке
или ошибке скрипта. Не используйте `settings.set` для временного скрытия и не
выключайте `manual left` / `manual right`: они управляют направлением anti-aim.
Между скриптами действует обычный приоритет последнего override; освобождение
своего override не отменяет чужой.

Исторический порядок category/name у этих полей различается. Используйте точно:

| Назначение | Вызов |
| --- | --- |
| Общая видимость | `settings.get("manual arrows", "anti aim")` |
| Активна левая сторона | `settings.get("manual left", "anti aim")` |
| Активна правая сторона | `settings.get("manual right", "anti aim")` |
| Скрыть штатную левую | `settings.override("anti aim", "manual left arrow", false)` |
| Скрыть штатную правую | `settings.override("anti aim", "manual right arrow", false)` |
| Расстояние между стрелками | `settings.get("anti aim", "manual arrow distance")` |
| Размер и цвет | `anti aim / manual arrow size`, `anti aim / manual arrow color` |

Направления — effective состояния настроек/биндов, а не подтверждение применения
углов движком. При обеих активных сторонах штатный HUD показывает обе. Общий
переключатель стрелок и раздельные флаги влияют только на их рисунок.
Штатные стрелки имеют заливку и чёрный контур около 1px с непрозрачностью 64%
от альфы основного цвета, как у watermark. При рисовании размер ограничен
2–24px, расстояние — 20–300px, без перезаписи сохранённых значений.

Примеры: [custom_manual_arrows.lua](examples/custom_manual_arrows.lua) — свои
стрелки без файлов; [manual_arrow_images.lua](examples/manual_arrow_images.lua) —
картинки с сохранением штатной стороны, если её файл не загрузился. Оба
освобождают скрытие при выключении/смерти. Native HUD дополнительно учитывает
камеру, cinematic/time-freeze; Lua-примеры проверяют доступность и жизнь игрока.

### Watermark и логи

В категории `widgets` доступны `show watermark`, `show keybinds`, `show logs`. Например, собственная watermark:

```lua
local enabled = ui.create("checkbox", "custom_watermark", "Custom watermark", true)
events.on("paint", function()
    if not ui.get(enabled) then
        settings.override("widgets", "show watermark", nil)
        return
    end
    settings.override("widgets", "show watermark", false)
    local width = client.screen_size()
    render.text(width - 210, 20, "My Skeet interface", {180,220,255,255})
end)
```

`widgets / show logs` управляет экранными hitlogs, `impacts / console logs` —
их выводом в игровую консоль. В меню это Misc → Interface → Hitlogs и Console
Hitlogs. Оба переключателя выключены по умолчанию; явно сохранённые значения
старого конфига учитываются. Скрытие очищает очередь видимых сообщений: при
повторном включении старые скрытые hitlogs не появляются. Это не удаляет историю
Lua-консоли и не отключает сбор игровых событий/уведомлений Lua.

Положение штатной панели кейбиндов сохраняется в конфиге. При открытом меню
перетащите её за заголовок Keybinds; заголовок доступен и без активных биндов.
Штатная панель рисуется под меню и его всплывающими окнами; при пересечении
меню перекрывает её. Перетаскивание через область меню не захватывает его клики.
Поля `widgets / keybinds x` и `widgets / keybinds y` имеют тип number, в пикселях
от левого верхнего угла viewport до начала первой строки. Начальные значения:
`x=100`, `y=-1`; отрицательный `y` означает автоматическую позицию
`screen_height * 0.5 + 34`. При перетаскивании записываются реальные x/y.
Отрисовка ограничивает позицию границами viewport; NaN/бесконечные координаты
заменяются начальной позицией при отображении.

Используйте `settings.get`/`set`/`override` с этими точными ключами; возвращается
число, неизвестный ключ вызывает обычную ошибку настройки. Чтение доступно из
paint; set/override меняют только UI-положение по общим правилам настроек выше.
После смены конфига начатое перетаскивание отменяется и используется позиция
нового конфига. Временный override координат действует до снятия владельцем;
для сохраняемой позиции используйте обычное перетаскивание либо settings.set
без активного override этих полей. FFI-ограничения от этого не меняются.

## Бинды

Поля `impacts` для трассеров/хитмаркеров, их единицы и диапазоны описаны в
[Трассеры и попадания](IMPACTS.ru.md). Старый `hitmarker glow` перенаправляется
на `hitmarker bloom`; новые скрипты используют каноническое имя.

`settings.bind(category, name)` читает `{key, mode, active}` у штатного setting с биндом. Для изменения передайте оба аргумента `key` и `mode`. `key=0` снимает клавишу. В текущей реализации `mode=0` — toggle, `mode=1` — hold_on; входное устаревшее значение `2` нормализуется к toggle. На отдельный hold_off не рассчитывайте.

`settings.binds()` возвращает штатные бинды и checkbox-бинды активных Lua. Поля записи: category, name, key, mode, active, value. Список включает неактивные бинды; для своей панели фильтруйте записи самостоятельно. `value` — значение настройки, `active` — состояние бинда, поэтому это не всегда взаимозаменяемые поля.

Для своего checkbox используйте `ui.bind`, а не `settings.bind`. Для клавиши отдельного окна используйте `ui.window_bind`. Нажатие клавиши можно просто наблюдать через `client.key_down(vk)`; эта функция не потребляет клавишу и не блокирует её в CS2.

## Категории оружия

`settings.weapon_profiles()` выдаёт 34 профиля огнестрельного оружия в порядке меню. Поля: item_id, key, name, legacy_group, rage_category, legit_category. Zeus, ножи и гранаты в этот список не входят.

Для поиска категории по активному оружию сопоставляйте `item_id`, затем используйте `rage_category` или `legit_category` для чтения. Совпадение категории не разрешает запись боевых полей. Старые групповые категории не являются точным выбором конкретного оружия; для новых скриптов используйте возвращённые индивидуальные имена.
