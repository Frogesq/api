# Команды, движение, prediction и anti-aim

## Порядок обработки

Команда проходит через Lua `create_move`, read-only `pre_rage`, затем штатные prediction и модель движения/AA/Rage. После возврата pipeline вызываются `prediction`, `post_rage`, при выключенном Rage — `pre_legit` и `post_legit`, затем `post_move` и `finalize_command`. Завершающая синхронизация кнопок и CRC остаётся штатной.

Записывать команду разрешено только в create_move. Post-события нужны для наблюдения результата. Если pipeline не дошёл до требуемой стадии публикации, post-события не гарантированы.

## Снимок команды

`cmd.get()` возвращает таблицу:

| Поле | Значение |
|---|---|
| number | Номер команды |
| tick | Client tick базовой команды |
| buttons | Маска удерживаемых кнопок с учётом своего pending-запроса |
| buttons_changed, buttons_scroll | Текущие native-состояния дополнительных масок; pending-запись здесь ещё не отражена |
| history_count | Число записей input history, только чтение |
| forward, side, up | Нормализованные оси, учитывающие свой pending-запрос |
| angles | Vector3 углов, учитывающий свой pending-запрос |
| phase, writable | Текущая фаза; writable=true только в create_move |

Эта таблица — копия. Присваивание `cmd.get().forward = 1` ничего не меняет в игре. Используйте setters.

## Запрос движения

`cmd.set_movement(forward,side,up)` ограничивает каждую конечную ось диапазоном −1…1; up необязателен и по умолчанию равен 0. Forward положителен вперёд. **Side положителен влево**, как в текущей модели движения; отрицателен вправо. Поля side у снимков используют тот же знак.

`cmd.set_button(mask,pressed)` меняет разрешённые кнопки. Для нескольких кнопок объединяйте маски через `|`. Доступны:

| Кнопка | Маска |
|---|---:|
| jump | 2 |
| duck | 4 |
| forward | 8 |
| back | 16 |
| moveleft | 512 |
| moveright | 1024 |
| speed | 65536 |

`attack=1` и `attack2=2048` разрешаются только для подтверждённой активной гранаты. Наличие `buttons.use/reload/zoom/score/inspect` в таблице констант позволяет распознавать их при чтении, но не разрешает запись.

`cmd.set_button_state(mask,held,changed,scroll)` явно задаёт три boolean-состояния разрешённых битов. Для обычного удержания используйте более простой set_button. Изменение held через set_button формирует соответствующие changed-биты при применении.

Не смешивайте противоположные запросы направления без необходимости. При set_movement направление выводится из осей; этот запрос заменяет аналоговые subtick-импульсы движения и соответствующие направляющие биты до native pipeline. Он не создаёт интерфейс произвольного subtick-редактирования.

## Когда запрос применяется

Setters сначала меняют pending-запрос скрипта. Применение происходит после успешного выполнения всех его create_move-обработчиков. Ошибка или запрос выгрузки до применения отбрасывает его. Неудачный api.protect восстанавливает pending-запрос до входа в защищённый блок.

Для движения/кнопок требуется существующий protobuf кнопок; если он недоступен, запрос не публикуется. Нет гарантии, что принятый Lua-запрос попадёт на сервер: позднее штатная обработка может изменить или отклонить команду.

Скрипты выполняются по порядку имён в реестре. Поздняя запись одного поля может заменить раннюю. Успешный grenade claim блокирует дальнейшую запись этой команды другим скриптом. Не запускайте несколько управляющих скриптов, рассчитывая на случайный порядок их имён.

## Bhop и strafe

`movement.claim("bhop")` или `movement.claim("strafe")` отключает выбранный штатный режим на текущую команду после успешного dispatch. В следующей команде право нужно запросить снова. Все остальные native-функции продолжают работать.

```lua
local enabled = ui.create("checkbox", "bhop", "Lua bhop", false)
events.on("create_move", function()
    if not ui.get(enabled) then return end
    local state = movement.context()
    if not state then return end
    movement.claim("bhop")
    cmd.set_button(buttons.jump, client.key_down(32) and state.on_ground)
end)
```

Для собственного стрейфа заявляйте strafe и задавайте оси до предсказания. Лестницы, состояния смерти и отсутствие данных обрабатывайте отдельно. [lua_strafe.lua](examples/lua_strafe.lua) — простой пример, а не обещание оптимальной физики для каждого состояния игры.

## Prediction

`movement.context()` и его псевдоним `prediction.before()` возвращают prestate текущей команды либо nil. Origin, networked velocity, absolute_velocity, flags, friction и stamina относятся к состоянию до штатного prediction. Absolute_velocity не является прогнозом. `phase` здесь равен pre.

`prediction.result()` возвращает фактический снимок одной штатной native-транзакции: valid, command_number, phase, tick, flags, move_type, origin, velocity, landed, landed_fraction. Phase равен native_prediction. До результата, при invalid prediction или другой команде возвращается nil.

Это не повторное предсказание уже финальной команды после всей модели движения. У API нет prediction.simulate, управления restore journal или записи weapon state. Для вывода в paint сохраните копию результата из события prediction; учитывайте, что она относится к предыдущему обработанному command_number.

## Anti-aim

Собственная логика AA выбирает значения зарегистрированных настроек `anti aim`. Штатный AA должен быть включён пользователем. Список текущих полей и типов получите через `settings.list("anti aim")`.

```lua
events.on("create_move", function()
    local state = movement.context()
    if not state then return end
    settings.override("anti aim", "rotation", state.on_ground and 35 or -60)
end)
```

Native AA применяет свои проверки состояния, выстрела, use и гранат. `cmd.set_angles` не служит для переписывания firearm-углов: он разрешён только после grenade claim. Заменять результат готового выстрела в finalize_command нельзя.

Штатные aim/scanning/accuracy/autostop/shot-publication алгоритмы не являются заменяемыми Lua-компонентами. При этом любое движение меняет позицию и скорость, а значит условия стрельбы; неизменность результатов при произвольном движении скрипта не гарантируется. Штатная подготовка выстрела сохраняет право изменить движение ради автостопа после Lua-входа.

Автоматический выбор хитбоксов рейджа выполняется внутри этого штатного пути.
Lua не получает callback выбора кости или обхода Baim/Lethal Baim. Shot-события
наблюдают уже опубликованный выстрел; постоянный Lethal Baim не разрешает скрипту
публиковать атаку или менять углы огнестрельного оружия. Области наблюдений
combat.damage/hitboxes/hitchance не задают области прицеливания рейджа.
