# Lua в Skeet

Руководство по Lua API 3. Среда: **Lua 5.5.0**, модуль **cffi-lua/libffi**. Скрипты могут создавать интерфейсы, рисовать, работать с настройками и игровыми данными, управлять движением и готовить броски гранат.

## С чего начать

1. Прочитайте [установку и первый скрипт](QUICKSTART.ru.md).
2. Выберите нужную задачу в таблице ниже.
3. Уточните сигнатуры в [справочнике API](API_INDEX.ru.md). Для подсказок редактора используйте [api.lua](api.lua) и [ffi.lua](ffi.lua).
4. Возьмите подходящий [готовый пример](EXAMPLES.ru.md).

## Границы возможностей

Обычный Lua API не предоставляет замену аимбота, изменение сканирования, shot history или публикацию собственного firearm-выстрела. Настройки стрельбы доступны для чтения; косметические цвета — исключение. Настройки anti-aim и движения доступны через разрешённые поля `settings`.

Prediction возвращает снимки штатного расчёта; произвольной повторной симуляции движения нет. Для гранат доступны приблизительные траектории с отскоками, предпросмотр броска и позиции горящих очагов. Это не гарантия серверной точки взрыва или точной границы урона. `radar` предоставляет общий снимок и преобразование координат для своих панелей. Проверить наличие интерфейсов можно через `api.capabilities()`.

FFI позволяет выполнять native-код с правами процесса. Он не ограничен правилами обычного Lua API, не является песочницей и не даёт стабильных адресов внутренних функций Skeet. Обычные Lua-проверки не защищают от неверного указателя или намеренного изменения памяти через FFI.

Если руководство поставляется с собранным EXE, `build.json` содержит версию интерфейса и контрольные суммы этого комплекта. Наличие описания функции само по себе не заменяет проверку её поведения в вашей версии игры.
