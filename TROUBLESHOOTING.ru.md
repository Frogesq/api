# Ошибки и проверка скрипта

## Порядок проверки

1. Выключите скрипт и сохраните его исходник.
2. Прочитайте **первую** ошибку в Lua-журнале: следующие могут быть следствием первой.
3. Проверьте `api.version`, имена методов и [фазу callback](EVENTS.ru.md).
4. Уменьшите пример до одного контрола и одного callback.
5. Добавляйте ресурсы и игровые действия по одному. Для FFI сначала проверьте прототип, архитектуру, размеры и время жизни владельцев.

Синтаксическая проверка не проверяет engine ABI, наличие модели, GPU-ресурс или native DLL. Успешная загрузка также не означает, что нужный игровой callback уже был вызван.

## Частые случаи

| Симптом или сообщение | Причина и действие |
|---|---|
| Скрипт не отображается | Проверьте папку `%LOCALAPPDATA%\skeet` и расширение `.lua`, а не `.lua.txt` |
| `attempt to call a nil value` | Метод отсутствует или стандартная библиотека не открыта; сверить справочник и Lua 5.5-окружение |
| `attempt to index a nil value` | Нет игрока, камеры, оружия, prediction или записи; проверять nil перед чтением полей |
| Попытка индексировать число после world_to_screen | Метод возвращает x,y,on_screen, а не таблицу |
| `available only in command callbacks` | Вызван cmd/combat/trace/movement из paint/load/game_event |
| `command writes require create_move` | Перенести setters в create_move; post-события оставить для чтения |
| `attack requires an active grenade claim` | Маска запрещена для обычной записи или нет фактической гранаты |
| `another script owns this grenade command` | Другая Lua уже заняла команду; отключить конкурирующие управляющие скрипты |
| `aim/shot settings are read-only` | Поле стрельбы не предоставлено для Lua-записи; проверить writable |
| `render drawing is only available in paint` | Перенести render-вызов в paint; внутри XUI использовать xui-рисование |
| `this function requires its own xui window callback` | XUI-контрол вызван вне callback своего окна |
| `unbalanced native UI scope` | Неверный порядок begin/end или push/pop; закрывать в обратном порядке |
| `duplicate control id` | Контрол создан повторно или id совпал; создавать один раз |
| `combo index is 1-based` | Индекс начинается с 1 |
| `unknown texture handle` | Handle чужой/устарел, либо не проверен nil после загрузки |
| `texture_limit`, `font_limit`, `resource_bytes_limit` | Превышен общий кэш; прекратить создание уникальных ресурсов каждый кадр |
| `budget_exceeded` | Слишком много работы; изучить kind/scope, разбить расчёт, при recovering завершить callback |
| `Lua memory limit exceeded` | Превышен Lua allocator; убрать бесконечное накопление строк/таблиц |
| `queue_full` / `rate_limited` у console | Не отправлять команду каждый кадр; снизить частоту |
| Собственный XUI checkbox не сохраняется | Его значение хранит Lua; записывать в storage при changed |
| create_tab успешен, но вкладки не видно | Текущий backend хранит метаданные; видимые страницы создаются в XUI-окне |

## Проверка движения и гранат

Проверяйте без остальных Lua, затем добавляйте их по одному. Сначала наблюдайте state и command_number, потом включайте управление. Положительный side означает **влево**. Пример helper может отменяться из-за ручного ввода, native movement, смены оружия или препятствия — прочитайте его статус.

Снимок prediction может быть nil. Не подставляйте нулевую скорость как будто предсказание успешно. При появлении результата сопоставьте command_number с тем, что вы сохраняли.

После отпускания граната не возвращается вызовом cancel. Проверка на столе/в Lua-макете не доказывает server-side точность jump/run throw. После обновления игры повторно проверьте сохранённые позиции.

## Проверка FFI

При access violation процесс может завершиться без обычной Lua-ошибки. Проверьте версию DLL, все C-объявления, pointer/value, размер буфера, число аргументов и жизнь callback. Не пытайтесь исправить неверный native-указатель добавлением api.protect.

Временно замените внешний вызов простой работой с собственным ffi.new-буфером. Если она проходит, это не доказывает корректность внешней DLL — только позволяет локализовать проблему. Не используйте адреса от другой сборки Skeet.

Для сообщения об ошибке сохраните имя/версию скрипта, версию API, первый traceback, минимальный пример, порядок действий и сведения о внешних файлах. В комплекте с EXE идентичность выпуска указана в build.json.
