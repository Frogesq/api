# События

## Подписка

`events.on(name, callback)` возвращает целочисленный id подписки. `events.off(id)` отключает свою подписку и возвращает, была ли она активна. На одно событие можно зарегистрировать несколько обработчиков; они выполняются в порядке регистрации. Значение, возвращённое обычным callback, не заменяет игровые данные.

```lua
local subscription
subscription = events.on("paint", function()
    client.log("This handler ran once")
    events.off(subscription)
end)
```

## Доступные события

| Имя | Когда вызывается | Данные callback |
|---|---|---|
| `paint` | Проход Lua-отрисовки | Пустая таблица |
| `create_move` | До штатного командного pipeline | Пустая таблица; команда читается через cmd |
| `pre_rage` | После Lua-запросов, до native pipeline | Пустая таблица; cmd только для чтения |
| `prediction` | После возврата штатного pipeline и проверки стадии публикации | Пустая таблица; снимок через prediction.result |
| `post_rage` | После штатной обработки Rage | Пустая таблица |
| `pre_legit` | Перед штатным Legit, когда Rage выключен | Пустая таблица |
| `post_legit` | После этого вызова Legit | Пустая таблица |
| `post_move` | После указанной командной обработки | Пустая таблица |
| `finalize_command` | Перед завершающей синхронизацией кнопок и CRC | Пустая таблица |
| `frame_stage` | Уведомление стадии игрового кадра | `{stage=целое число}` |
| `game_event` | Скопированное уведомление игрового события | Таблица GameEvent |
| `shutdown` | Штатная выгрузка скрипта | Пустая таблица |

События `pre_rage` и `post_rage` обозначают границы командного пути. Они не дают доступ к выбору цели или редактированию выстрела. Подписок `rage_targets`, `rage_scan`, `rage_select`, `rage_fire`, `rage_shot` нет.

Командные post-события могут отсутствовать, если native pipeline завершился раньше. `create_move` также не является таймером, работающим независимо от состояния игры. Для часов интерфейса используйте `client.time`, для отрисовки — `paint`.

## Разрешённые фазы

| Операция | Где использовать |
|---|---|
| Изменение движения, movement claim, grenade claim/cancel | Только `create_move` |
| Чтение cmd, movement, combat и trace.line | Командные события |
| Результат prediction | `prediction` и следующие командные события; проверять nil |
| `render.*`, загрузка render-ресурсов, геометрия меню | Только `paint`; в XUI-окне используйте xui-рисование |
| `xui.*`, кроме регистрации окна | Callback именно своего XUI-окна |
| Подготовка chams-материалов | Верхний уровень при загрузке |
| Подготовка audio.preload | Верхний уровень при загрузке |

Некоторые функции вроде проекции и информации о кадре допускают более широкий контекст; создавайте графические ресурсы и рисуйте только в предусмотренном графическом callback. `frame_stage`, `game_event`, `shutdown` не предоставляют cmd.

## Игровые события

Каждый GameEvent содержит `name`. Поля зависят от события и доступных данных. Это копия, поэтому таблицу разрешено хранить после выхода из callback; сами сведения при этом устаревают.

| Поля | Назначение |
|---|---|
| `userid`, `attacker` | Индексы controller; `0` обозначает локального игрока, nil — отсутствующий или неразрешённый участник |
| `position` | Vector3 для `bullet_impact` |
| `dmg_health`, `damage` | Урон здоровью в `player_hurt`; damage — псевдоним dmg_health |
| `dmg_armor` | Урон броне |
| `health`, `armor` | Оставшиеся здоровье и броня |
| `hitgroup` | Игровая группа попадания, не индекс bone/hitbox |
| `weapon` | Скопированное имя оружия события |

```lua
events.on("game_event", function(e)
    if e.name ~= "player_hurt" or e.attacker ~= 0 then return end
    if e.dmg_health == nil then return end
    client.log("Damage", e.dmg_health, "weapon", e.weapon or "unknown")
end)
```

Нельзя обращаться к `e.position.x`, не проверив наличие `e.position`. Событие урона не связывает автоматически попадание с конкретным Lua-расчётом damage или hitchance.
